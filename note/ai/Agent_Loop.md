# Agent Loop

当代 Agent 已经不再用编排工具固定工作流程，而是让LLM自己决定工具调用和任务安排，靠循环来负责执行工具，收集结果，再执行工具，收集结果，直到完成任务（或者说模型觉得自己完成任务了）。

这种架构本质上是经典的 ReAct（Reasoning + Acting）模式。

## Agent loop 解决什么问题

LLM刚出现时候，交互方式无非一种：用户发消息，LLM回复，用户和模型的交流只有纯粹的文字内容。GPT-4 带来了工具调用，让LLM可以调用外部工具，传入参数来完成各种工作，等于给LLM接上了手脚。任务越复杂，涉及的工具越多，模型需要借助各种工具收集信息，规划，执行修改，验证结果。

Agent loop 在这里的任务就是以下几点：

1. 调用 LLM，取得模型的回复。
2. 检查回复中有没有工具调用。
3. 有则执行工具，并把结果写入上下文。
4. 再次调用 LLM，直到没有后续操作或者出现终止条件。

这其中 LLM 是做决策的核心，工具用来执行各种操作，loop 调度整个过程。

## 为什么不用固定编排了

主要还是模型能力变强了。Dify，LangChain 这种固定编排工作流在 LLM 自己的强大规划能力面前像个新兵蛋子，传言字节在 2026年 11月 已经放弃工作流产品 Coze 了。AI时代，学得越晚，走的弯路越少。

以目前时间点（2026年11月），主流 agent 设计倒也没有完全抛弃工作流方式，只是对于很多任务已经不需要预先编排层次非常细致的流程。

> GPT-6-sol-chat 曰：
> 对于高不确定性、探索性强、执行路径难以预先穷举的任务，LLM 自主 Loop 通常比固定工作流更自然。
> 但 Workflow 仍然有不可替代的职责

工作流目前的价值在于定义一些强约束，而开放性的任务交给 agent 自主规划完成。

## 主流 Agent loop 范式

### 1. ReAct / Tool-Calling Loop

LLM决策，调用工具，返回结果，然后循环直到模型不调用工具，给出回答。

以当前时间点（2026年11月）推理模型遍地都是的情况（赞美 DeepSeek R1 开源），`Thought → Action → Observation` 这种输出格式早就不是必须的了，模型基本都训练了工具调用能力。

### 2. Plan-and-Execute

```
用户任务
   ↓
Planner 制定计划
   ↓
Executor（内部也是 Agent Loop）
   ↓
更新任务进度
   ↓
必要时重新规划
   ↓
完成任务
```

一般会维护一套动态更新的 TODO 清单，其中 Planner 可以是单独的 LLM 调用，也可以是同一个 Agent 使用的 update_plan / todo_write 工具。
