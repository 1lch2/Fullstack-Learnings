# JS中延迟代码执行

## setTimeout 0毫秒

```js
setTimeout(() => {
  // 被延迟执行的操作
}, 0);
```

## queueMicrotask

```js
queueMicrotask(() => {
  // 被延迟执行的操作
});
```

## 对比

如字面意义，queueMicrotask 会往微任务队列中push一个新的微任务，相比 setTimeout 的宏任务优先级更高，不需要等待更长时间。

|          | `queueMicrotask`                 | `setTimeout(fn, 0)`                      |
| -------- | -------------------------------- | ---------------------------------------- |
| 队列类型 | **微任务** (microtask)           | **宏任务** (macrotask)                   |
| 执行时机 | 当前同步代码执行完后**立即**执行 | 等待下一轮事件循环，且所有微任务清空之后 |
| 渲染插队 | 会阻塞渲染                       | 两轮宏任务之间浏览器有机会渲染 [5]       |
| 嵌套延迟 | 无限制                           | 嵌套超过 5 层，最小延迟强制为 **4ms**    |

## 使用场景

- **`queueMicrotask`**：需要"以最快速度"在当前任务完成后执行，且不能被渲染或其他任务插队。Promise 的 `.then()` / `await` 底层就是微任务。[9]
- **`setTimeout(fn, 0)`**：需要**让出主线程**让浏览器有机会渲染或处理用户输入，常用于拆分长任务、或在 DOM 更新后等待布局完成再读取尺寸。
